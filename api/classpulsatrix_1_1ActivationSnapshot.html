Detailed Description

A copyable, self-contained record of every activation cached during one forward pass, plus the node ids in topological order and each node's op_type/label metadata.

Note
Holds no reference to the ComputationGraph or ExplainerContext it was captured from – deliberately. ExplainerContext::forward_pass() replaces its graph and activation cache wholesale on every call, and ComputationGraph is move-only (std::vector<std::unique_ptr<Node>>), so a snapshot that referred back to either would be invalidated by the very next forward pass. Copying the activation Tensors and the small amount of per-node metadata instead is what makes two snapshots from two different forward passes simultaneously alive and correct – the capability activation patching needs (campaign campaign_exai_dl_library_mechanistic_interpretability, Phase 4).
NodeIds are comparable across two snapshots taken from the same ExplainerContext: its module chain is fixed for its lifetime, so every forward pass builds a structurally identical graph (same node count, same op-type sequence, same ids), differing only in the cached values.
Constructed by ExplainerContext::activation_snapshot(), not assembled by hand.

Note
No cross-validation between the three arguments: this constructor is reached only from ExplainerContext::activation_snapshot(), which builds all three from one consistent graph in a single pass. An empty snapshot (all three empty) is a well-formed value, not an error – it is what a context that has not yet run a forward pass produces.
