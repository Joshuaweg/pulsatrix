Detailed Description

y = f(x), elementwise, for one of the backend's activations. No parameters.

Note
LRP passes relevance through unchanged, the standard rule for a pointwise nonlinearity (Montavon et al. 2019) and the one AttnLRP and LXT apply to a transformer MLP's GELU.

bool pulsatrix::ActivationModule::supports_lrp_rule ( LRPRule  rule) const
inlineoverridevirtual

Whether propagate_relevance() implements rule (no silent fallback: callers such as ExplainerContext::relevance_pass() throw rather than run a module on a rule it does not implement).

Note
Default: only LRPRule::Epsilon, the rule every module implements. Overridden by LinearModule / Conv2DModule (all rules), by parameter-free pass-through modules whose relevance rule does not read the config at all, and by SequentialModule (all layers).
