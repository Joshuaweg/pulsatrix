Detailed Description

An explanation that says what it supports (XAI-3): the attribution together with the question and reason it was made for, the method and its settings, the results of the checks the plan asks for, and caveats derived from those results and from the method's known failure modes.

BuildExplanation() runs an attribution explainer and every check ExplanationPlanner (XAI-2) plans for it that pulsatrix can run on one input: faithfulness against random orderings, stability, conservation, the randomization test, the null-model baseline and aggregation over a dataset. ReportExplanation() builds the same report from checks run elsewhere, for explainers that don't return an attribution (a probe, persistent homology). Either way the caveats follow from the report alone (DeriveCaveats()), so a stored report can be re-checked.

ExplanationRequest request;
request.question = XaiQuestion::Why;
request.reason = XaiReason::Justify;
request.traits.access = ModelAccess::Gradients;
request.traits.can_reinitialize = true;
request.method = "IntegratedGradients";
request.baseline = zeros; // what IG integrated from, for the conservation check
const Explanation e = BuildExplanation(request, x,
[&](const Tensor& in) { return ig.explain(ctx, in, zeros, 0, 64, &backend); },
[&](const Tensor& in) { return model.forward(in); }, &model);
if (!e.supports_reason()) std::cout << DescribeExplanation(e); // the blocking caveats say why
